# Scriptures library — notes for Claude sessions

Live site: https://scriptures.craadle.org/ (published from `main`). Owner: Darwin Goyal (`goyaldarwin`).

**Read first:** `docs/START-HERE.md` (the documents, the repositories, the status of each work), `docs/PLAYBOOK.md` (every rule and preference), `docs/HOW-TO.md` (procedures), `docs/LIBRARY.md` (data format).

Non-negotiables:
- Accuracy above all, then unambiguity, clarity, consistency, structure; never traded for distance from a copyrighted translation. Never write a scripture text from memory; texts come from the owner's sources (or web sources the owner allows), with every choice in the work's `reconciliation.md`.
- Never route around a blocked site or a copyright limit. `goyaldarwin/scriptures-data` is private, always; never copy its raw files here.
- Before writing, reviewing or applying any meaning: `python3 tools/meanings/sanskrit_dict.py fetch && python3 tools/meanings/sanskrit_dict.py check` (Monier-Williams and Apte live outside the repo; a new session never has them), then read `tools/meanings/style.md` §1; for the Mānas, follow `docs/HOW-TO.md`, "Write our own meanings for a kāṇḍa of the Mānas"; for another work, `tools/meanings/style.md` §10, checking with `overlap.py` against that work's copied sources.
- Before every commit: `python3 tools/site/check.py` (the build, then regen_check, history_check, smoke_test and ux_test side by side; about 25 minutes on a 2-core machine, 21 in CI; `--fast` for a data-only change, about 4 minutes, the browser tests then run in CI). Diff regenerated data before committing it.
- Audio timings follow `tools/audio/METHOD.md`, always: (1) Whisper (OpenAI's speech recogniser, the `transcribe` workflow) places each verse roughly and cuts the recording into windows; (2) **MMS** — Meta's Massively Multilingual Speech forced aligner (torchaudio `MMS_FA`), which is given the known text and finds where each line is sung, with a wildcard between lines for refrains and music — sets the exact starts (and ends), moved by the recording's lean, unsure ones (score < 0.5) kept from Whisper and listed to check; (3) automatic checks flag verses out of place (MMS vs Whisper > 2 s, low score, out of pace for their length, out of order, listener flags) and fix them (re-align between trusted neighbours, snap to the singing's onset, else spread by length and list); (4) the owner's starts and ends set by ear always win. A verse overrunning the next is the next verse's start being late. A new recording uses steps 2–5 at once; one already timed from Whisper alone switches once steps 2–5 score better on the owner's by-ear starts for it, with the figures in its `aligned.md` (`tools/audio/METHOD.md`). Long Actions runs cap their parallel jobs (`max-parallel: 14`).
- `git pull` before pushing: the `timing` workflow pushes to `main` when the owner sends audio times from the app.
- Files state the current state only: no dates, change logs, "was / used to / superseded" notes or stories. Git is the history. A new owner preference or lesson changes the rule in `docs/PLAYBOOK.md` in the same commit as the change.
- No `pkill -f` (it kills the session's own shell); GitHub GraphQL is unavailable — use `gh api` (REST).
- Reply to the owner in plain words: what changed, what to check, one next step.
